# Finance Tracker working instructions

Before planning or changing this application, read VERSION, DEVELOPMENT.md,
ROADMAP.md, CHANGELOG.md and RELEASE-WORKFLOW.md. Inspect Git status, branch,
HEAD and release tags; verify remote main and GitHub Releases when accessible.
Report unavailable evidence instead of substituting conversation memory.

VERSION is the application/package version, not proof of deployment. Distinguish
checkout, published release and user-reported installed version. Do not bump a
version or rebuild an already released version merely for documentation work.
Historical UPDATE and test reports retain their original versions and claims.

Keep ROADMAP.md current as work is completed or discovered. Record current work,
verification and limitations in DEVELOPMENT.md. Add delivered changes to
CHANGELOG.md under Unreleased until promotion; follow RELEASE-WORKFLOW.md for
release evidence and publication. Update these records in the same change as the
work they describe. Do not duplicate them in a separate BUILD/status document.

Preserve existing functionality. Use isolated test data; never migrate or change
live financial data as part of development verification. Deployment requires
explicit authorisation. A feature listed on the roadmap is scope, not permission
to implement it during a documentation-only task.
